# AstrBot 多 Bot 工作群协作插件

把一个 QQ 群设为工作群。一个 AstrBot 实例担任协调 Bot，读取群里的需求；其他实例按模型能力承接子任务。协调 Bot 在群里公布分工、收集结果、汇总并共享知识。所有实例安装同一插件，填写同一个群号、协调 Bot QQ 号和共享密钥。

## 本机后台通道（0.6.2）

Bot 之间的心跳、任务派发、认领、结果回传、知识同步等内部协议消息，默认改走**本机后台通道**，不再以 `[WG]` 身份出现在群聊里；群里只保留给人看的分工通知、进度和最终结果。

- AstrBot Launcher 的同机实例默认共用 `.astrbot_launcher/workgroup_channel`。其他安装方式需要在各实例面板中把「后台共享目录」设成同一个可访问路径。
- 每个实例在 `presence/` 里登记自己的 Bot 号；`queue/` 按目标 Bot 号投递，写入和认领都用原子改名，避免重复消费；过期消息 120 秒清理。
- `transport_mode=local`（默认）：内部消息只走本机通道；写入失败记入日志，不会退回群里。`auto`：本机优先，对端未登记或写入失败时可能退回群内 `[WG]`，用于兼容旧版本。`group`：旧行为，全部走群消息。
- 群内 `[WG]` 接收逻辑保留，便于处理尚未升级的实例。要让群内不再出现新发出的 `[WG]`，所有参与实例均需升级并设为 `local`；旧版本实例仍可能发送群消息。
- 心跳不再依赖群里发消息，由后台每 60 秒经本机通道发送一次；协调 Bot 侧收到后照旧更新在线状态。

## 可视化视图（0.6.2）

在 AstrBot WebUI 的**插件详情**里打开「workgroup」视图，可直接展开「工作群配置」填写并保存当前实例的群号、管理员、Bot、能力表、共享密钥、任务范围、超时、讨论和知识同步等设置，无需跳到插件配置栏。除任务记录路径需重载插件外，保存后立即应用。多个实例需要分别保存；共享密钥不会回显，留空表示保持已有密钥。

视图还可查看模式、任务、成员模型、实际 Token 用量、子代理数量、共享知识、黑话与最近 100 条工作日志。页面每 8 秒自动刷新，通过 AstrBot Plugin View 桥接读取数据。群内启停、模式切换和知识管理仍只接受主要管理员指令。

在**协调 Bot 的视图**中有两块「AI 智商调节」面板，每个 Bot 各有 **5 档滑动栏**：第 1 档快速、第 2 档精简、第 3 档标准、第 4 档深入、第 5 档复核。它们实际控制思考投入，不改变模型本身的能力、订阅额度或 AstrBot 的全局模型设置。旧版保存的 0–100 数值仍有效，并按对应范围显示在五档中；重新拖动时写入该档的代表值。

- **工作模式**：用于协作任务。复核档在初稿后额外调用一次执行 Bot 的模型检查结果。保存后从**下一项任务**生效；任务创建时固定档位，并通过签名任务消息传给执行 Bot。自动分工会对复杂任务轻微参考档位，仍优先考虑已配置能力和公开模型评分。
- **常态模式**：用于各 Bot 的普通聊天，不影响工作任务。旧配置默认**不启用**常态调节，移动滑动栏后启用；「恢复原样」可关闭。高档对符合条件的普通纯文本额外复核一次；工具调用、代码、结构化或多媒体回复不做二次改写。协调 Bot 会把设置通过签名消息同步到对应实例；Bot 暂时离线时，在其下一次工作群消息后补同步。

两个模式的高档都可能增加耗时和 Token 消耗。原有配置文件与任务记录继续可用，旧工作模式档位保留；新增常态模式初始显示 50，但未启用前不改变日常回复。

## 功能

- 只接管配置的**一个**工作群；未填完整配置时不接管任何群。
- 协调 Bot 用当前实例的 AI 模型识别需求，最多拆成四个子任务。填写能力表时按优势、弱项分配；留空时自动发现持有共享密钥的 Bot，读取各实例当前模型，并参考公开 Arena 榜单的 Agent、Text、WebDev 排名。无法匹配榜单时不编造评分，按已知信息与固定顺序分配。榜单缓存 24 小时，离线时使用缓存。
- 可选任务前 Bot 协商：参与 Bot 判断自己是否适合分工，不适合时协调 Bot 尝试改派；最多等待约 20 秒。
- 已完成子任务结论自动写入插件自己的共享知识库，并通过签名的内部消息同步给其他 Bot。新接入 Bot 会收到最近 20 条知识及现有黑话。后续规划和执行会检索相关知识；知识库最多保留 200 条，每条记录来源 Bot、任务号和时间。
- 主要管理员可用 `/知识库 添加 标题=内容`、`/知识库 查询 关键词`、`/知识库 列表`、`/知识库 删除 编号` 管理知识；`/黑话 添加 词语=解释`、`/黑话 删除 词语`、`/黑话 列表` 管理共享词汇。
- 主要管理员发送 `/工作` 或 `/聊天`，整个工作群中的 Bot 各自切换，群内不重复回复；发送 `@指定Bot /工作` 或 `@指定Bot /聊天` 时，只有被点名的 Bot 切换并确认。旧 `/切换模式` 会被拦截但不再切换。
- 聊天模式的 Bot 不参加工作任务分配；切换状态由 Bot 心跳告诉协调 Bot。视图会提示是否收到其他 Bot 的心跳，便于检查群号、协调 Bot QQ 和共享密钥是否一致。
- 在聊天群模式，若 `astrbot_plugin_private_companion` 已启用且开放扩展 API，相关共享知识和黑话会作为请求上下文交给 companion；两插件各自的数据保持独立。
- 视图中 Token 用量只统计本插件直接发起、且模型提供 usage 的调用；子代理数量来自本实例 AstrBot 的已注册 handoff，其他 Bot 通过心跳上报。
- Bot 之间默认用本机后台通道接力，内部消息带共享密钥签名、发送者白名单、目标 Bot、时间窗口与任务尝试次数校验。后台通道不可用时，任务会等待或超时，可在工作日志查看。普通群成员伪造任务不会被执行。
- 执行 Bot 使用自己的 AI 模型回复分配的子任务；协调 Bot 聚合结果。子任务超时或报错可改派给另一 Bot。任务和已完成的执行结果保存在每个实例本地。
- 默认记录位置为各 AstrBot 实例的 `data/plugin_data/astrbot_plugin_workgroup/tasks.json`。
- 工作群监听器使用 `sys.maxsize - 2` 优先级，并调用 `event.stop_event()`，使普通低优先级插件不再接管该群消息。
- **只有配置的主要管理员 QQ 号**能在群里输入 `/work stop`、`/work start`、`/work status`、`/work tasks`。暂停状态会在每个实例本地保存。
- `off / mention_only / relevant / always` 四种回复范围。默认 `relevant`，识别工作需求；普通聊天只有在被唤醒时回复。`always` 会处理普通聊天，可能产生较多模型费用。

## 安装与配置

1. 把本文件夹安装到每个参与协作的 AstrBot 实例。AstrBot Launcher 同机实例使用默认「本机后台」即可；其他同机部署需要在各实例面板中指定同一个「后台共享目录」。跨机部署且没有共享目录时选择 `group`；此模式的内部消息会出现在群里。
2. 在每个实例的插件视图中填写同一个 `work_group_id`、`owner_qq_id`、`coordinator_bot_id` 和 `protocol_secret`。`bot_roster` 可留 `{}` 自动发现，也可填写下方能力表。自动发现时建议填写 `bot_ids` 限定允许加入的 Bot。密钥用随机长字符串，不要发到群里。
3. 在每个实例的 AstrBot 中配置可用的 AI 模型。一个 QQ 号只对应一个参与实例。
4. 在群里由主要管理员输入 `/work status` 检查，然后发一个明确任务。协调 Bot 应回复任务号与分工，执行 Bot 回传内部协议，最后协调 Bot 汇总。

能力表例子（替换成真实 QQ 号）：

```json
{
  "10000001": {"name": "协调", "strengths": ["规划", "写作"], "weaknesses": ["代码"], "priority": 10},
  "10000002": {"name": "开发", "strengths": ["Python", "代码"], "weaknesses": ["排版"], "priority": 8},
  "10000003": {"name": "校对", "strengths": ["测试", "审查"], "weaknesses": ["视觉设计"], "priority": 5}
}
```

`coordinator_bot_id` 填 `10000001`。手动模式下所有实例的能力表须一致；共享密钥始终须一致。自动发现依赖 Bot 之间能看见彼此的 QQ 群消息；首次发现前只能给已知 Bot 分工。

## 权限和实际边界

本插件在 AstrBot **插件事件处理器**中设置极高优先级，但不能覆盖 AstrBot 核心会话控制、平台封禁、未启用的插件或比它更早停止事件的处理器。它也不能阻止有实例管理权限的人在 WebUI 关闭插件。要避免其他插件在工作群抢先拦截，应在工作群使用的 AstrBot 配置文件中检查插件启用范围。主要管理员的 `/work stop` 是本插件的群内停止入口。

内部协议只让已配置的 Bot 用自己的模型生成文本，不执行群消息传来的脚本、文件操作或外部工具。多 Bot 完成的是**文本协作与结果汇总**，不是跨设备共享文件或自动运行代码。`aligner.py` 是原工作区保留的本地文件合并工具，未自动接入群任务。
