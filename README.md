# AstrBot 多 Bot 场景工作台

## 1.2.1：真实 QQ 在线状态与一键完整检测

- 在线状态改为读取 AstrBot 平台适配器对应的 QQ 登录状态，不再使用面板访问时间；QQ 在线与协作通道连接分别显示，明确离线的成员不会参加新任务。
- 新增“一键完成检测”：一次检查基础配置、QQ 登录、内部通道读写、模型供应商、协调模型调用、任务审核 JSON 和本机插件联动，并给出逐项处理建议。
- 一键检测会实际调用一次协调模型验证审核格式，产生少量 Token；其他插件与 QQ 检测均为本机读取。
- QQ 个人号检测兼容 AstrBot 官方 CQHttp 客户端的直接 `call_action()` 接口，也兼容旧包装器的 `client.api.call_action()`，避免已在线账号被误标为“待检测”。
- 若 OneBot 不返回 `get_login_info`，会使用 AstrBot 消息事件已确认的 `self_id`，并同时验证 CQHttp 反向 WebSocket 仍有活动连接；只有两项同时成立才判定在线。
- AstrBot 4.29.1 / aiocqhttp 1.4.x 会直接从活动反向 WebSocket 客户端表的账号键识别 QQ，优先级高于 API 探测；Launcher 实例码会变化，不参与 Bot 身份判断。
- 若 AstrBot“机器人”页面为空，诊断会明确显示“未接入平台机器人”，主代理与子代理卡片也会同步显示实际未接入状态，不再长期停留在“待检测”。QQ 桌面客户端在线不代表 AstrBot 已连接该账号。

## 1.2.0：协调操作栏与跨实例代理控制

- 总览新增可视化“协调操作栏”，可统一切换工作/休闲模式、开启或关闭多 Bot 协作、选择保留/去掉人格、立即同步工作区并运行体检。成员实例可看到一致状态，但全局按钮只允许协调 Bot 操作。
- 同工作区实例现在会同步公开场景、主代理/子代理栏、岗位、模型服务和两套思考强度。协调 Bot 可控制其他 Bot 及其子代理；成员只能修改自己的代理。私有交接记忆、共享密钥和本机路径永不广播。
- 每个主代理与子代理增加任务分工下拉栏，内置“辅助协调、画图、编程 1、编程 2、资料检索、文案写作、数据分析、测试复核”，也可自定义。规划提示会读取这些岗位并按代理 ID 派单。
- 每个主代理与子代理可从对应 AstrBot 实例已启用的模型供应商列表中选择模型；协调 Bot 会经内部通道读取成员的可选列表。执行时优先使用指定 Provider，找不到时安全回退当前会话模型，并保留自定义 ID 入口。
- 任务分配可选“按岗位栏与计划分工”或“模型能力自动协调”。后者只由协调 Bot 联网更新公开 Arena 排名缓存，并结合当前模型、岗位和思考强度分配；联网失败时保留缓存并回退已有信息。
- 设置页拆成“Bot 公开运行设置”和“当前实例私有连接设置”，去除了人格、超时、讨论等重复入口。协调 Bot 可调整其他实例的公开运行设置，离线实例在下次心跳时补同步。
- 子代理已有明确岗位时，岗位会自动作为适用任务说明，不再重复报警；`[WG]` 协议在 `auto/local` 模式只走本机内部通道，不再回退或显示到群聊。
- “一键同步全部”会同步场景、主代理与子代理、岗位、模型、两套强度、公开设置和在线状态；“一键修复内部通道”会统一同机共享目录并重新登记实例。
- 在线状态直接读取 AstrBot 平台适配器对应的 QQ 登录状态；QQ 个人号优先使用本机 OneBot `get_login_info/get_status`。打开或关闭插件面板不会改变在线状态；内部心跳只表示协作通道是否连通。明确离线的成员不会参与新任务分配。

## 1.1.0：主代理与子代理统一入场景

- 每个场景新增代理栏：主代理固定在首位；AstrBot 已启用的 SubAgent 会通过本机配置自动同步到所属 Bot 场景，也可建立手动子代理。
- 所有主代理与子代理统一提供“工作时 / 休闲时”五档思考强度。主代理休闲强度用于普通聊天；子代理休闲强度作为休闲链路调用时的预设。
- 任务规划可指定场景内的具体代理，派单会携带代理身份与工作强度；无效代理自动安全回退主代理。
- 工作人格可选“去掉日常人格”或“保留当前 AstrBot Persona”。人格只在本机读取，失败时回退场景口吻，不联网。
- 自动检测 `astrbot_plugin_private_companion`、`astrbot_plugin_master_aware` 与屏幕伙伴/日记公开接口；检测完全在本机进行。日记仅通过公开的 `shared_work` 接口记录工作活动，不直接修改其他插件文件。
- 控制台新增四步使用提示、代理当前状态、统一强度滑动栏和插件联动状态；不再恢复旧版重复的工作/常态两套独立面板。

## 1.0.0 大更新：从“群协作”到“场景工作台”

这次更新把原来的多 Bot 分工升级为一套完整工作闭环，主要参考「淋雨家的工作台」的方法论，并针对 AstrBot 群协作做了独立实现和简化：

- **场景**：每个 Bot 有明确角色、职责、边界与四字段表达方式；自动从 Bot 成员表补齐，也可在视图中编辑或新增。
- **项目**：每个正式任务自动生成项目，记录 owner 场景、状态、摘要、验收判据、下一步、任务号和证据。
- **派单与回执**：规划阶段要求给出可验证的整体验收判据；执行 Bot 固定按“结论、证据、还差什么”回执，完成后写入回执台账。
- **场景记忆**：每个场景维护不超过 4 KB 的当前交接，以及关键决策和踩坑；记忆不依赖聊天会话，可在视图或群内更新。
- **归档**：完成、受阻或待验收项目可移入只读式归档台账，历史记录不会被删除。
- **机制体检**：检查基础配置、协调 Bot、协作通道、成员场景、场景边界、项目 owner、验收判据及完成证据，直接返回差异集合。
- **新控制台**：插件视图重做为总览、场景、项目、记忆与交接、协作记录、设置六个区域，保留原有任务、知识、日志与配置能力。
- **向下兼容**：沿用 0.6.5 的 `tasks.json`、群模式、签名协议、本机通道、知识库、黑话、思考强度和管理员审核；旧状态首次加载时自动补工作台数据。

新增群内命令：

```text
/场景 列表
/项目 列表
/交接 scene-机器人QQ 当前项目、最近变化、下一步和卡点
/体检
```

原有 `/工作`、`/聊天`、`/任务`、`/协作`、`/work`、`/知识库` 和 `/黑话` 命令保持不变。

## 0.6.5 更新（历史）

- 常态模式思考强度提示改为追加到当前请求的临时用户内容，不再改写 `system_prompt`；保留去重和 JSON/XML 输出场景跳过保护。旧版 AstrBot 若没有该接口，会跳过提示注入。
- 移除未被插件调用的 `aligner.py` 本地文件合并工具，避免误以为插件会自动操作工作站文件。
- 主要管理员发送 `/工作` 时所有 Bot 进入工作状态，默认开启协作；工作任务使用协作提示，不调用日常人格。发送 `/聊天` 时所有 Bot 退出工作状态，默认关闭协作，消息交还 AstrBot 的常规聊天与人格链路。协调 Bot 通过签名后台消息同步全群模式，并统一回复切换结果；`@Bot /工作`、`@Bot /聊天` 仍可定向切换单个 Bot。若主动回复范围设为 `off`，工作模式仍会拦截普通群消息，避免落回人格聊天。
- 工作模式中可用 `/协作 开`、`/协作 关`、`/协作 状态` 独立控制多 Bot 分工。关闭协作后，任务仍由协调 Bot 处理，不派给其他成员。聊天模式下协作始终不执行；需先 `/工作`。用 `/任务 具体需求` 明确下达任务，即使主动回复范围是 `off` 或仅被唤醒也会受理。旧的自动识别任务方式保留。
- 管理员任务道德审核默认开启：拦截明确要求违法行为、伤害他人或侵犯他人隐私的任务。关闭后跳过插件审核，也不会发送插件审核忠告。这个开关不改变外部模型或平台的限制。

## 工作站文件夹（0.6.3）

在插件视图的「工作群配置」里，将当前 AstrBot 实例可访问的任意文件夹绝对路径填入「工作站文件夹」并保存。插件会验证目录，在面板中显示路径与最多 40 个顶层目录项，并把这些名称交给本实例的协作模型作为任务背景。各实例可以分别指定不同目录；旧配置留空时行为不变。此功能不读取文件内容、不自动修改文件，也不运行代码。

把一个 QQ 群设为工作群。一个 AstrBot 实例担任协调 Bot，读取群里的需求；其他实例按模型能力承接子任务。协调 Bot 在群里公布分工、收集结果、汇总并共享知识。所有实例安装同一插件，填写同一个群号、协调 Bot QQ 号和共享密钥。

## 本机后台通道（0.6.2）

Bot 之间的心跳、任务派发、认领、结果回传、知识同步等 `[WG]` 协议消息，默认只走**本机后台通道**，不出现在群聊里；群里只保留给人看的分工通知、进度和最终结果。

- 通道是同机共享目录：默认 `data/plugin_data/astrbot_plugin_workgroup/channel`，可用 `local_channel_dir` 指定。多个实例要指向**同一个**目录（同一台机器上路径一致即可）。
- 每个实例在 `presence/` 里登记自己的 Bot 号；`queue/` 按目标 Bot 号投递，写入和认领都用原子改名，避免重复消费；过期消息 120 秒清理。
- `transport_mode=auto`（默认）和 `local`：`[WG]` 只写入共享目录，写入失败也不会回退到群消息。插件不再提供把内部 JSON 发进 QQ 群的模式。
- 旧配置没有通道字段时按 `auto` 处理；升级后应为所有同机实例填写同一个可写的 `local_channel_dir`。
- 心跳不再依赖群里发消息，由后台每 60 秒经本机通道发送一次；协调 Bot 侧收到后照旧更新在线状态。

## 可视化视图（0.6.2）

在 AstrBot WebUI 的**插件详情**里打开「workgroup」视图，可直接展开「工作群配置」填写并保存当前实例的群号、管理员、Bot、能力表、共享密钥、任务范围、超时、讨论和知识同步等设置，无需跳到插件配置栏。除任务记录路径需重载插件外，保存后立即应用。多个实例需要分别保存；共享密钥不会回显，留空表示保持已有密钥。

视图还可查看模式、任务、成员模型、实际 Token 用量、子代理数量、共享知识、黑话与最近 100 条工作日志。页面每 8 秒自动刷新，通过 AstrBot Plugin View 桥接读取数据。群内启停、模式切换和知识管理仍只接受主要管理员指令。

在**协调 Bot 的视图**中有两块「AI 智商调节」面板，每个 Bot 各有 **5 档滑动栏**：第 1 档快速、第 2 档精简、第 3 档标准、第 4 档深入、第 5 档复核。它们实际控制思考投入，不改变模型本身的能力、订阅额度或 AstrBot 的全局模型设置。旧版保存的 0–100 数值仍有效，并按对应范围显示在五档中；重新拖动时写入该档的代表值。

- **工作模式**：用于协作任务。复核档在初稿后额外调用一次执行 Bot 的模型检查结果。保存后从**下一项任务**生效；任务创建时固定档位，并通过签名任务消息传给执行 Bot。自动分工会对复杂任务轻微参考档位，仍优先考虑已配置能力和公开模型评分。
- **常态模式**：用于各 Bot 的普通聊天，不影响工作任务。旧配置默认**不启用**常态调节，移动滑动栏后启用；「恢复原样」可关闭。高档对符合条件的普通纯文本额外复核一次；工具调用、代码、结构化或多媒体回复不做二次改写。协调 Bot 会把设置通过签名消息同步到对应实例；Bot 暂时离线时，在其下一次工作群消息后补同步。

两个模式的高档都可能增加耗时和 Token 消耗。原有配置文件与任务记录继续可用，旧工作模式档位保留；新增常态模式初始显示 50，但未启用前不改变日常回复。

## 功能

- 只接管配置的**一个**工作群；未填完整配置时不接管任何群。
- 协调 Bot 用当前实例的 AI 模型识别需求，最多拆成四个子任务。填写能力表时按优势、弱项分配；留空时自动发现持有共享密钥的 Bot，读取各实例当前模型，并参考公开 Arena 榜单的 Agent、Text、WebDev 排名。无法匹配榜单时不编造评分，按已知信息与固定顺序分配。榜单缓存 24 小时，离线时使用缓存。
- 可选任务前 Bot 协商：参与 Bot 判断自己是否适合分工，不适合时协调 Bot 尝试改派；最多等待约 20 秒。
- 已完成子任务结论自动写入插件自己的共享知识库，并通过签名群消息同步给其他 Bot。新接入 Bot 会收到最近 20 条知识及现有黑话。后续规划和执行会检索相关知识；知识库最多保留 200 条，每条记录来源 Bot、任务号和时间。
- 主要管理员可用 `/知识库 添加 标题=内容`、`/知识库 查询 关键词`、`/知识库 列表`、`/知识库 删除 编号` 管理知识；`/黑话 添加 词语=解释`、`/黑话 删除 词语`、`/黑话 列表` 管理共享词汇。
- 主要管理员发送 `/工作` 或 `/聊天`，整个工作群中的 Bot 各自切换，群内不重复回复；发送 `@指定Bot /工作` 或 `@指定Bot /聊天` 时，只有被点名的 Bot 切换并确认。旧 `/切换模式` 会被拦截但不再切换。
- 聊天模式的 Bot 不参加工作任务分配；切换状态由 Bot 心跳告诉协调 Bot。视图会提示是否收到其他 Bot 的心跳，便于检查群号、协调 Bot QQ 和共享密钥是否一致。
- 在聊天群模式，若 `astrbot_plugin_private_companion` 已启用且开放扩展 API，相关共享知识和黑话会作为请求上下文交给 companion；两插件各自的数据保持独立。
- 视图中 Token 用量只统计本插件直接发起、且模型提供 usage 的调用；子代理数量来自本实例 AstrBot 的已注册 handoff，其他 Bot 通过心跳上报。
- Bot 之间默认用本机后台通道接力，`[WG]` 消息带共享密钥签名、发送者白名单、目标 Bot、时间窗口与任务尝试次数校验；内部通道不可用时会记录错误，但不会把协议发到群里。普通群成员伪造任务不会被执行。
- 执行 Bot 使用自己的 AI 模型回复分配的子任务；协调 Bot 聚合结果。子任务超时或报错可改派给另一 Bot。任务和已完成的执行结果保存在每个实例本地。
- 默认记录位置为各 AstrBot 实例的 `data/plugin_data/astrbot_plugin_workgroup/tasks.json`。
- 工作群监听器使用 `sys.maxsize - 2` 优先级，并调用 `event.stop_event()`，使普通低优先级插件不再接管该群消息。
- **只有配置的主要管理员 QQ 号**能在群里输入 `/work stop`、`/work start`、`/work status`、`/work tasks`。暂停状态会在每个实例本地保存。
- `off / mention_only / relevant / always` 四种回复范围。默认 `relevant`，识别工作需求；普通聊天只有在被唤醒时回复。`always` 会处理普通聊天，可能产生较多模型费用。

## 安装与配置

1. 把本文件夹安装到每个参与协作的 AstrBot 实例。使用默认 `transport_mode=auto`，并把所有实例的 `local_channel_dir` 指向同一个可写目录。跨机器部署时需要使用操作系统共享盘或网络挂载目录；插件不会用 QQ 群传输内部 JSON。
2. 在每个实例的插件视图中填写同一个 `work_group_id`、`owner_qq_id`、`coordinator_bot_id` 和 `protocol_secret`。`bot_roster` 可留 `{}` 自动发现，也可填写下方能力表。自动发现时建议填写 `bot_ids` 限定允许加入的 Bot。密钥用随机长字符串，不要发到群里。
3. 在每个实例的 AstrBot 中配置可用的 AI 模型。一个 QQ 号只对应一个参与实例。
4. 在群里由主要管理员输入 `/work status` 检查，然后发一个明确任务。协调 Bot 应回复任务号与分工，执行 Bot 回传内部协议，最后协调 Bot 汇总。

能力表例子（替换成真实 QQ 号）：

```json
{
  "10000001": {"name": "协调", "strengths": ["规划", "写作"], "weaknesses": ["代码"], "priority": 10},
  "10000002": {"name": "开发", "strengths": ["Python", "代码"], "weaknesses": ["排版"], "priority": 8},
  "10000003": {"name": "校对", "strengths": ["测试", "审查"], "weaknesses": ["视觉设计"], "priority": 5}
}
```

`coordinator_bot_id` 填 `10000001`。手动模式下所有实例的能力表须一致；共享密钥始终须一致。自动发现通过共享目录里的内部心跳完成，不依赖 Bot 互相看见 QQ 群消息。

## 权限和实际边界

本插件在 AstrBot **插件事件处理器**中设置极高优先级，但不能覆盖 AstrBot 核心会话控制、平台封禁、未启用的插件或比它更早停止事件的处理器。它也不能阻止有实例管理权限的人在 WebUI 关闭插件。要避免其他插件在工作群抢先拦截，应在工作群使用的 AstrBot 配置文件中检查插件启用范围。主要管理员的 `/work stop` 是本插件的群内停止入口。

内部协议只让已配置的 Bot 用自己的模型生成文本，不执行群消息传来的脚本、文件操作或外部工具。多 Bot 完成的是**文本协作与结果汇总**，不是跨设备共享文件或自动运行代码。
